Clean Architecture 5 Tầng CQRS + MediatR
1. TỔNG THỂ
Clean Architecture (5 Tầng)
Phân lập 5 Projects riêng biệt. Tầng ngoài phụ thuộc tầng trong theo nguyên lý Đảo ngược phụ thuộc (Dependency Inversion). Business Core cô lập hoàn toàn.
2. ĐIỀU PHỐI
CQRS & MediatR Bus
Tách rẽ tuyệt đối giữa Commands (Ghi dữ liệu) và Queries (Đọc dữ liệu). MediatR đóng vai trò xe buýt nội trình kết nối lỏng Controller và Handler.
3. DỮ LIỆU
Dual DbContext (EF Core 9)
Tách rẽ 2 DbContext: VnuaCareDataContext (bật Change Tracker cho Ghi) và VnuaCareReadDataContext (ép AsNoTracking() giúp Đọc tăng tốc 3-5x).
4. BỘ NHỚ ĐỆM
Cache-Aside (Redis + Fallback)
Đọc dữ liệu từ RAM Redis trong ~1ms. Khi Ghi dữ liệu sẽ tự động xóa cache liên quan. Nếu Redis gặp sự cố, hệ thống tự động fallback về SQL Server.
5. BẢO MẬT
JWT Stateless & Rotation
Đăng nhập kép với loginIdentifier (Username hoặc Email), băm mật khẩu BCrypt. Cặp Access Token (2h) và Refresh Token (7 ngày) chống Replay Attack.
6. PHỄU XỬ LÝ
ExecuteFuntion Funnel
Phễu hứng tập trung trong ApiControllerBase: Khởi động Stopwatch bấm giờ, bắt trọn Exception toàn cục và bọc dữ liệu trả về vào ApiResponse<T>.

Hệ Thống Token, Xác Thực JWT & Refresh Token Rotation

Phân tích toàn diện cơ chế cấp phát, bảo vệ, chu kỳ làm mới Access Token / Refresh Token và an toàn mật khẩu với BCrypt.

Bảo Mật Cấp Doanh Nghiệp
1. JWT Access Token (Stateless)
  • Chuẩn: JSON Web Token mã hóa HMAC-SHA256 với Secret Key.
  • Thời hạn: 120 phút (2 giờ) cấu hình tại JwtSettings:AccessTokenExpirationMinutes.
  • Claims nhúng: UserId, Username, Email, Role (SUPER_ADMIN, HEALTH_ADMIN, DOCTOR, STAFF).
  • Ưu điểm: Không lưu trạng thái trên Server RAM, hỗ trợ mở rộng ngang Microservices.
2. Refresh Token Rotation
  • Cơ chế sinh: 32 bytes ngẫu nhiên an toàn qua RandomNumberGenerator.Create() chuyển thành chuỗi Base64.
  • Lưu trữ DB: Lưu tại cột vc_users.refresh_token và refresh_token_expiry_time (thời hạn 7 ngày).
  • Xoay vòng (Rotation): Mỗi lần cấp Access Token mới sẽ hủy bỏ Refresh Token cũ và sinh mã mới ghi đè vào DB.
  • Chống Replay Attack: Ngăn chặn kẻ gian dùng lại token bị rò rỉ.
3. BCrypt & ContextAccessor
  • Mật khẩu BCrypt: Tự sinh muối ngẫu nhiên (Salt) và tính toán qua 4,096 vòng lặp (Cost factor 12).
  • Chống Rainbow Table: Không thể đảo ngược hoặc tra cứu mật khẩu gốc.
  • IContextAccessor: Trích xuất danh tính và phân quyền RBAC tức thì trong mọi Handler mà không cần truy vấn lại CSDL.
Triển Khai Thực Tế Trong Mã Nguồn C# (.NET 9)

Sinh Access Token & Refresh Token (JwtService.cs)

// 1. Sinh Access Token kèm Claims và ký số HMAC-SHA256
public string GenerateAccessToken(IEnumerable<Claim> claims)
{
    var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(_secretKey));
    var creds = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);

    var token = new JwtSecurityToken(
        issuer: _issuer,
        audience: _audience,
        claims: claims,
        expires: DateTime.UtcNow.AddMinutes(120),
        signingCredentials: creds
    );
    return new JwtSecurityTokenHandler().WriteToken(token);
}

// 2. Sinh Refresh Token ngẫu nhiên 32 bytes an toàn mật mã học
public string GenerateRefreshToken()
{
    var randomNumber = new byte[32];
    using var rng = RandomNumberGenerator.Create();
    rng.GetBytes(randomNumber);
    return Convert.ToBase64String(randomNumber);
}

Hệ Thống Cache Đa Tầng (Redis & Cache-Aside Pattern)

Chiến lược tăng tốc độ phản hồi API dưới 5ms, giảm tải 90% truy vấn đọc đến SQL Server và kiến trúc Resiliency tự phục hồi.

Redis Distributed Cache
Luồng Xử Lý Cache-Aside (Lazy Loading) Trong Dự Án
1
Kiểm tra Cache Redis (Cache Check)
Handler gọi _cacheService.GetOrCreate<T>(key, factory). Hệ thống kiểm tra chuỗi JSON tương ứng với Key trong Redis.
2
Trường hợp Cache Hit (< 1ms)
Dữ liệu có sẵn trong Redis, thực hiện deserialize JSON sang DTO và trả về ngay lập tức mà không cần chạm vào SQL Server.
3
Trường hợp Cache Miss -> Truy vấn SQL & Nạp lại
Thực thi factory function truy vấn SQL Server qua VnuaCareReadDataContext (AsNoTracking), serialize JSON và nạp vào Redis với Sliding Expiration: 300s.
4
Xóa Cache Khi Ghi Dữ Liệu (Cache Invalidation)
Khi có lệnh INSERT / UPDATE / DELETE (Command), Handler tự động gọi _cacheService.Remove(key) để đảm bảo tính nhất quán dữ liệu.
Cơ Chế Tự Phục Hồi (Fault-Tolerance & Fallback) Khi Redis Gặp Sự Cố

Nếu Redis Server bị mất kết nối, quá tải hoặc tắt đột ngột, API tuyệt đối không bị văng lỗi 500. Khối try-catch sẽ tự động ghi log cảnh báo và truy vấn thẳng xuống SQL Server để phục vụ người dùng trơn tru:

RedisCacheService.cs - Fallback Resiliency 
public async Task<TItem?> GetOrCreate<TItem>(string key, Func<Task<TItem>> createItem, DistributedCacheEntryOptions? options = null)
{
    // Kiểm tra cấu hình có bật Cache không
    if (_config["AppSettings:EnableCache"] == "true")
    {
        TItem? cacheEntry;
        try
        {
            var itemString = await _distributedCache.GetStringAsync(key);
            if (string.IsNullOrEmpty(itemString))
            {
                // Hết hạn trượt 300 giây (5 phút)
                options ??= new DistributedCacheEntryOptions().SetSlidingExpiration(TimeSpan.FromSeconds(_timeLive));

                cacheEntry = await createItem(); // Đọc từ SQL Server
                var item = JsonSerializer.Serialize(cacheEntry);
                await _distributedCache.SetStringAsync(key, item, options); // Nạp lại Redis
            }
            else
            {
                cacheEntry = JsonSerializer.Deserialize<TItem>(itemString); // Cache Hit
            }
        }
        catch (Exception ex)
        {
            // Bắt ngoại lệ Redis gặp sự cố: Tự động Fallback đọc trực tiếp từ SQL Server
            Log.Error($"Có lỗi xảy ra khi xử lý dữ liệu từ redis - {ex.Message}");
            cacheEntry = await createItem();
        }
        return cacheEntry;
    }
    return await createItem();
}

                Tại sao bắt buộc phải truyền cancellationToken?

                Khi cán bộ hoặc bác sĩ đang gửi yêu cầu tạo hồ sơ nhưng bấm Hủy (Cancel) trên trình duyệt hoặc mất kết nối mạng (Network Drop):

                - Nếu KHÔNG có token: SQL Server vẫn âm thầm thực thi câu lệnh SQL đến cùng, làm chiếm dụng CPU và giam giữ kết nối trong Connection Pool vô ích.

                - Khi CÓ token: ASP.NET Core lập tức gửi tín hiệu hủy, EF Core ngắt kết nối đến SQL Server (Command.Cancel()), giải phóng tài nguyên tức thì cho các yêu cầu khác!
              

            

          


          
          
Các Phương Thức LINQ & EF Core Quan Trọng Khác

          

            

              
.AsNoTracking()

              

                Tắt bộ theo dõi thay đổi (Change Tracker) của EF Core. Giúp giảm 50%-70% RAM và tăng tốc độ đọc dữ liệu lên 2 đến 3 lần. Được áp dụng trên 100% các câu truy vấn trong thư mục Queries/.
              

            


            

              
.Select(...) (Projection)

              

                Chỉ định chính xác các cột cần lấy từ SQL Server ánh xạ sang DTO (Data Transfer Object). Ngăn chặn lỗi Over-fetching (lấy thừa các cột text dài, mô tả, ảnh).
              

            


            

              
.Where(...) Động (Dynamic Query)

              

                Sử dụng IQueryable<T> cho phép ghép nối các điều kiện lọc (theo năm, khoa phòng, trạng thái) vào Expression Tree và chỉ thực thi 1 câu lệnh SQL duy nhất khi gọi kết thúc.
              

            


            

              
.Skip(...) & .Take(...) (Phân trang)

              

                Chuyển dịch thành cú pháp chuẩn SQL Server: OFFSET @skip ROWS FETCH NEXT @take ROWS ONLY. Bắt buộc phải đi kèm với .OrderBy(...) để đảm bảo thứ tự bản ghi ổn định.

              Luồng Dữ Liệu 6 Chặng
            

            

              Mọi tương tác từ Client (Web/Mobile) đều đi qua một chu trình 6 chặng được chuẩn hóa nghiêm ngặt, đảm bảo tính phân tách trách nhiệm, hiệu năng cao và an toàn dữ liệu:
            


            

              

                
1. CLIENT

                
Gửi HTTP Request

                
Header Authorization: Bearer <JWT> + JSON Payload.

              


              

                
2. MIDDLEWARE

                
CORS & JWT Auth

                
Giải mã HMAC-SHA256, nạp Claims vào HttpContext.User.

              


              

                
3. CONTROLLER

                
ExecuteFuntion

                
Bấm giờ duration, bắt Exception tập trung, gọi MediatR.

              


              

                
4. MEDIATR BUS

                
Định Tuyến CQRS

                
Chuyển Command (Ghi) hoặc Query (Đọc) tới đúng Handler.

              


              

                
5. HANDLER

                
Thực Thi Nghiệp Vụ

                
Tương tác Dual DbContext (Write/Read) & Redis Cache-Aside.

              


              

                
6. RESPONSE

                
ApiResponse<T>

                
Đóng gói JSON chuẩn hóa kèm traceId và duration (ms).

Bản Đồ Kết Nối Giữa Các File (File Connection Topology)

              Kiến Trúc Phân Tầng Clean Architecture
            

            

              Mỗi file trong dự án đóng một vai trò nhất định và kết nối chặt chẽ với nhau thông qua Dependency Injection Container được thiết lập tại Program.cs:
            


            

              
              

                

                  
API

                  

                    
1. Tầng API Ngoại Vi

                    
VnuaCare.API

                  

                

                

                  • Program.cs: Khởi tạo DI, Dual DbContext, JWT, Redis, CORS.

                  • Controllers/Business/: Tiếp nhận HTTP request, phân nhóm Swagger.
                

                
Ủy thác qua: _mediator.Send() →

              


              
              

                

                  
BASE

                  

                    
2. Lớp Nền Tảng Dùng Chung

                    
VnuaCare.Shared

                  

                

                

                  • ApiControllerBase.cs: Hàm ExecuteFuntion bấm giờ Stopwatch & bắt lỗi.

                  • IContextAccessor: Trích xuất UserId, Role từ Claims JWT.

                  • ApiResponse<T>: Đóng gói JSON chuẩn.
                

                
Tiêm vào: Mọi Controller & Handler →

              


              
              

                

                  
CQRS

                  

                    
3. Trái Tim Nghiệp Vụ

                    
VnuaCare.Business (CQRS)

                  

                

                

                  • Commands/: Xử lý GHI (Create, Update, Delete).

                  • Queries/: Xử lý ĐỌC & Phân trang (GetFilter, GetById).

                  • MediatR: Tự động điều phối Command/Query tới đúng Handler.
                

                
Tương tác: Dual DbContext & Cache →

              


              
              

                

                  
DATA

                  

                    
4. Tầng CSDL (Dual DbContext)

                    
VnuaCare.Data

                  

                

                

                  • VnuaCareDataContext (Write): Bật Change Tracker cho Commands.

                  • VnuaCareReadDataContext (Read): Bật AsNoTracking() cho Queries.

                  • Systems/Context/: 24 Thực thể Entity C#.
                

                
Truy vấn: SQL Server Database →

              


              
              

                

                  
CACHE

                  

                    
5. Dịch Vụ Bộ Nhớ Đệm

                    
Services/CacheService

                  

                

                

                  • RedisCacheService.cs: Mô hình Cache-Aside (Sliding 300s).

                  • Fallback Resiliency: Tự động chuyển hướng sang SQL Server nếu Redis sập.

                  • Cache Invalidation: Xóa cache khi có Command ghi.
                

                
Giao tiếp: Redis Port 6379 →

              


              
              

                

                  
AUTH

                  

                    
6. Hạ Tầng Bảo Mật

                    
VnuaCare.Infrastructure

                  

                

                

                  • JwtService.cs: Sinh Access Token HMAC-SHA256 & Refresh Token 32 bytes RNG.

                  • PasswordHasher.cs: Băm & xác thực mật khẩu BCrypt với Salt ngẫu nhiên.
                

                
Bảo vệ: Toàn bộ phiên làm việc →
